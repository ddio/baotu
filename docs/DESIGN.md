# 設計筆記

這份文件記錄做這個遊戲時已經定案的事，以及為什麼。

## 定位

- 類型：State.io／Galcon 這一類的即時佔地遊戲。兵力同時是生產、防守和進攻的資源；資訊完全公開；行軍需要時間。
- 去掉營運設計：沒有內購、沒有越來越貴的升級、沒有體力。
- 單機優先，純靜態網站，沒有後端。介面只做繁體中文，沒有聲音，不放流量統計。
- 一局目標 5–8 分鐘。不提早判定勝負，最後的碾壓是樂趣的一部分；提供 2 倍速。

## 地圖

- 1901 年二十廳，加上 1909 年的花蓮港廳，再把紅頭嶼（蘭嶼）從臺東分出來，共 22 區。選它的原因：現代縣市有被包住的小城（基隆、嘉義市、臺北市），面積差到 77 倍；二十廳沒有被包住的區，本島最大與最小只差 6.5 倍。
- 以現代 358 個鄉鎮歸併而成，邊界是近似值。沒有金門、馬祖（當時不屬於臺灣總督府）。
- 連線共 46 條：一般 30、山路 10、航線 5、險航線 1。
  - **山路**：凡是翻越中央山脈的連線都是山路，行軍時間是一般的 3 倍，沒有例外。東部（宜蘭、花蓮港、臺東）因此是獨立的戰區，正常速度只能從北邊的基隆、深坑或南邊的恆春進去。
  - **航線**：澎湖到鹽水港（布袋嘴）、臺南（安平）、鳳山（打狗）；紅頭嶼到臺東、恆春。不另設速度，只是距離長。
  - **險航線**：澎湖到臺北，沿西海岸外海往北、從淡水河口進去，約 279 公里。行軍時間也是 3 倍（`roughFactor`），跟山路同一個數字，玩家只要記一種「慢」。地圖上畫成長短相間的線，會轉彎；連線可以帶中途的轉折點（`via`），軍隊的位置、城外、砲台射程都沿著這條彎線算。直線會壓過彰化到新竹的陸地，看起來像走陸路。它讓澎湖不只是南部外海的死角：佔了澎湖可以繞到臺北背後，單程大約 70 秒。
- **繞開第三個據點的路**（地圖 v3）：兩支敵對的軍隊在圖上靠近就打，不管是不是同一條路，所以兩個據點的直線要是從第三個據點旁邊擦過去，路過的軍隊會跟在那裡城外紮營的打起來。最明顯的是新竹—臺中的山路：直線從苗栗城外 14 單位穿過去，等於「跳過苗栗」的人會走進苗栗的城門口。有八條連線改成彎的（`tools/taiwan1901.config.mjs` 的 `BEND`，寫法跟險航線一樣）：新竹—臺中走內山、基隆—宜蘭沿東北角海岸、嘉義—臺南走東邊山腳、鳳山—澎湖和臺南—澎湖從外海繞，南投—嘉義、深坑—桃仔園、宜蘭—桃仔園只彎一點。標準是每條連線離別的據點 45 以上、離別的據點城外的紮營位置比遭遇距離（36）遠，`tests/map.test.ts` 會檢查。行軍時間仍然照直線距離算，每條連線都跟 v2 一樣，所以起點好壞、電腦對打的數字不用重量。
- 速度不是每條邊界各自的屬性，而是畫在地圖上的地形：畫了山脈的地方慢、長短相間的航線慢，其他都一樣。
- **紅頭嶼**是地圖 v2 加的，沒有特色的中立區。島照實際大小畫（寬約 18 個地圖單位，比據點的圖記還小），不放大：好不好按看的是手指離據點多近，不是島的輪廓，所以只靠航線連接的島（澎湖、紅頭嶼）點按範圍是 56，其他區 36。綠島留在臺東：它離臺東太近，獨立出來據點會擠在一起。
- 新的區只能加在最後面，舊的區編號不能動：記錄裡存的是區的編號。

## 規則

- 一次把該區的兵全部派出去（出發的區會空掉，要自己衡量後防）。派兵後該區進入冷卻。
- 兵沿著相鄰的區走，目標可以是任何一區，路線由遊戲決定：能只穿過自己的領地就走其中最快的，不行就走全圖最快的路。軍隊在路上第一個不是自己的區開打，打贏也留在那裡，不會一路打過去；那一區如果在軍隊抵達前已經變成自己的，就繼續往前。拉線時會畫出這條路，並標出會在哪裡開打。
- 城外：要停下來的軍隊（攻城或進駐）不走到據點中心，停在離據點 28 個地圖單位的地方（`gate`，`gateTick` 算出是這段路的第幾拍）。這個位置是規則的一部分，不是畫面上的修飾：遭遇和砲台都照這個位置算，畫出來的位置就是規則裡的位置。
- 圍城：軍隊到了別人的區不進城，停在城外，每拍跟守軍一個換一個（`siegePerTick`，一秒各少 10 個）。守軍先打光的那一拍佔領，剩下的兵開始進城；同時打光算守住，守軍剩 0。圍的時候守軍照樣長兵、砲台照樣打、對方援軍照樣進得去；那一區如果被別路的友軍先打下來，城外的兵就改成排隊進城。
- 進城：到了自己的區（增援，或剛打下來）也不是一瞬間進去，每拍進 3 個（`enterPerTick`，一秒 30 個，是圍城的三倍）。還在城外的兵仍然是路上的軍隊：會被靠近的敵軍抵銷、會挨砲。所以大軍增援要幾秒才進得完，剛打下來的城有一小段時間裡面只有幾個兵，這是可以被趁虛而入的空檔。畫面上隊伍繼續走進據點，據點的數字往上跳。原本是一到就整筆扣掉，數字一瞬間跳完，看起來像守軍沒被扣到；改成看得見的消耗。畫面上軍隊排在據點外面，城門口閃刀光，兩邊的數字一起往下掉。
- 遭遇：任何兩支不同陣營的軍隊，在圖上的直線距離在 36 個地圖單位以內（`clashRange`）就打起來，一兵換一兵，兵多的帶著剩下的繼續走。不管是不是同一條路：迎面來的不用等到交會、後面快的不用真的追上、從不同的路往同一個據點會合的也會打。因為城外離據點 28，比 36 小，所以圍城中從城裡派兵出來，不管往哪個方向都會先撞上城外的敵軍；同時圍一座城的兩家，如果城門靠得近也會互打。原本只看同一段路、而且要位置交會才算，手機上兩隊明明貼在一起卻沒事，看起來像漏判。任何兩個不同陣營都算敵對。
- 遭遇不是一碰就整隊抵銷：每一對每拍雙方各少 2 個（`clashPerTick`，一秒 20 個，比圍城快、比進城慢），打到其中一邊沒兵為止。打完一拍、旁邊還有活著的敵軍的軍隊算被纏住（`fight`）：停在原地，不前進、不攻城、也不進城；敵軍打光的那一拍就解除，當拍可以接著攻城或進城，下一拍繼續走。一支軍隊同時被兩支纏住，就每拍少兩份。原本是一拍算完，畫面上整隊一起消失，看不出是打輸的；現在兩隊對峙、中間閃刀光、點一顆一顆變少（3 個兵一顆點）。連帶的效果：打的時候砲台照打、兩邊的援軍趕得上加入；被圍的城派兵出城，城外那支要先把出城的打完才能回頭攻城，出城可以拖時間；在城外排隊進城的援軍會被攔下來。
- 援軍可以讓兵力超過上限（用來打破僵局），但超過上限就不再生產。
- 中立區不會長兵。
- 區的特色（每區最多一個）：
  - **大城**（臺北、臺中、臺南）：產兵快、上限高，中立時守軍多。
  - **砲台**（基隆、鳳山、澎湖）：射程（半徑 80，澎湖 130，地圖上畫成虛線圈）內的敵軍每 3 拍每支少一個兵，中立的砲台誰都打。澎湖原本沒人路過，砲台形同虛設；130 讓三條往南的航線大半在射程裡（鹽水港九成、臺南六成半、鳳山四成半），從南邊三條航線來搶的人，路上加圍城要挨 16–19 發（射程 80 的時候是 10–11 發）；從臺北走險航線來的因為慢，要挨 38 發。不再加大的原因：150 以上會蓋到鹽水港的據點（離 143），沒人佔的澎湖從開局就打鹽水港進出的軍隊，電腦對打時從鹽水港起家的勝率從 33% 掉到 17%。在圈裡待越久損失越多，圍城的時候也照打：路上大約少 5–8 兵，守軍每多 3 個就再多挨一發。中立的砲台（守軍 10）要 19–22 兵才拿得下，守軍 30 的要 51–56（走航線的 59–65），屯滿 100 的要 153 兵以上。從旁邊路過（臺北—深坑、蕃薯藔—阿猴）60 兵大約少 9–14 個，其中一半是在城外排隊進城的時候挨的；深坑和阿猴的據點本身就在圈內，在那裡圍城、進城或從那裡出發都會挨砲。原本的規則是「進攻砲台的兵只算三分之二」，數字對但看不出來為什麼，所以改成看得見的砲彈。兵力上限最高（100，一般 40、大城 70），長得不快但屯得多。拉線時的說明會先照規則把這一趟跑一遍（`forecast`：拿一份只有這支軍隊的副本跑到打完），所以砲台打掉幾個、拿不拿得下、會剩幾個都跟實際一致，沒算到的只有路上別的軍隊。電腦估砲台損失用的是比較省的 `shellLoss` 加上圍城那段的估算。
  - **糧倉**（彰化、鹽水港、阿猴）：第一個打下來的加 15 兵，每個糧倉一局只給一次，之後再換人都不加（`Region.spent`）。從糧倉起家的不算「打下來」，存糧留給第一個從他手上搶走的人。最早是每一方只給一次，但「為什麼這次沒加」看不出來；改成每次換人都加之後，兩家在糧倉來回搶等於一直憑空生兵，太強。現在一局一次，並且讓它看得出來：給過的糧倉，圖記從墨底變成空心，點它的說明也寫「存糧已經被拿走」。加兵時據點會鼓一下、有小點湧進去、飄一個「+15」。電腦把給過的糧倉當成一般的區估價。
  - **驛站**（新竹、嘉義、臺東）：從這裡出發的兵走得快。
  - 地圖上不用字標：每種特色一個圖記（城牆、砲、稻穗、驛旗），墨色圓底，掛在據點右上角；左下角有圖例。原本是地名旁的紅色小字印，手機上太小，要讀字才懂。圖記不用紅色，是因為紅色已經是其中一方的顏色。
- 開局 4 方（3 個對手）是預設。玩家自己選起點，AI 放在離玩家和彼此最遠的位置，不會從只靠航線的島（澎湖、紅頭嶼）開局。玩家可以選這兩個島，算是自找的難題：電腦對打時從紅頭嶼起家的勝率大約 13–22%（四方、均勢是 25%），從澎湖起家不到一成。
- 對手多不等於難（他們會互打）。難度調的是電腦的反應速度、一次能發動幾路進攻、進攻前要多幾分把握、多積極把後方的兵往前線送，以及會不會顧家（只有「強」會，見下面）（`src/sim/ai.ts` 的 `AI_PROFILE`）；三種難度用的是同一套規則，電腦不作弊。調完用 `npm run balance` 看勝率。
- 派兵是整區派光，所以電腦遇到敵軍正朝某區來時，那一區一律留下來守，不管守不守得住。試過「守不住就撤走」：三到五成的佔領會撲空，玩起來像守軍沒被扣掉。電腦只走自己領地內的路，不會像玩家那樣指遠處的目標。
- 改電腦的打法，用 `npm run duel` 跟前一版對打（`tools/duel.ts`）：同一批種子，新的坐 1 號對前一版、前一版坐 1 號對新的，各跟「前一版自己打自己」比，因為 1 號的位置本來就不是均勢。一輪 300 局，差 3 個百分點以內當作沒差。對打只量得出電腦之間誰強，量不出對人好不好玩。
- 試過、沒留下來的打法：挑目標時看地盤的形狀（拿下之後多幾個四周都是自己人的區就加分，跟別人的接觸變多就扣分，接觸按行軍時間打折、對著中立的只算三成五）。試了二十幾組權重和四種套用方式（全部目標、只算別人的區、只算身邊沒有中立區之後、不算中立的接觸），對前一版的勝率沒有一組變高，權重越大越低（3 方 46% 掉到 39–44%，4 方 28% 掉到 20–26%），一局還多 5–10 秒。原因是這張圖一局只有兩分鐘左右，勝負在搶中立區的那一段就決定了：扣接觸等於偏好死角、避開四通八達的區，擴張變慢；等到身邊沒有中立區才開始算的版本，300 局裡改變結果的不到 1 局。
- 同一輪還試了另外兩種，也沒留：「專心打一家」（正在交手的那一家、最弱的鄰居、最強的鄰居三種挑法，那一家的區加分）勝率持平或低 1–4 個百分點；「牽制」（進攻時順手派一小隊去目標隔壁、或去貼著自己地盤屯了兵的區，讓它不敢出兵）幾乎沒有機會出手，300 局裡改變結果的 0–2 局。原因是「強」每 1.2 秒想一次、多 1 個兵就出手，打起來是一大群小部隊互相進出，一局對別家的進攻指令將近 300 道，前線的區幾乎隨時都有敵軍正朝它來、本來就被綁住，沒有閒著的小隊可以拿去牽制。換成會屯兵、一次只打一路的對手（`REST="margin=8,attacks=1" npm run duel`）和「中」來比，結果一樣。連帶試的「來的只是一小隊、等它到時新長的兵就擋得住，就不必留守」也是持平。
- 「強」比較看重糧倉（存糧還在的算 16，弱和中是 12，一般的區 10）。700 局對打：自己坐 1 號沒有差（3 方 47.1% 對 47.1%，4 方 30.6% 對 30.3%），但 3 方時兩個對手都用新的，前一版坐 1 號的勝率從 47.1% 掉到 33.6%（4 方 30.3% 到 28.7%），一局多 1–3 秒。差別出在對手：他們的起點離玩家最遠，常在東部和南部，阿猴的糧倉對他們是近的。試過 14、16、20，差不多，取中間。
- 「強」會顧家（`careful`，弱和中不會）。起因是真人可以騙它：派兵是整區派光，它多 1 個兵就出門，家就空了；別的區被打，前線每一區又都整區跑去救，一支軍隊就能把一整排區引開，再走進空城。改了兩件事：
  - 出兵前先看隔壁別家屯的兵：那些兵走過來的時間，這一區新長的兵擋不擋得住。擋不住就不出門，除非要打的就是那一家，或要打的地方比自己這一區值錢（驛站、砲台、城）。沒有後面這個例外的話，自己坐 1 號更強（300 局，3 方 41.0%、4 方 34.3%），但幾個對手都這樣打的時候，前一版坐 1 號反而贏得比原本多（35.3%、32.7%，原本 33.0%、26.3%）；有這個例外，兩邊都是變強。
  - 正在被打的區缺多少補多少：自己的兵、已經在路上的援軍、對方走到加上圍城這段時間新長的兵都先扣掉；前線的區只在它真的缺、而且自己出門不會被撿走時才去救。
  - 700 局對打：坐 1 號對前一版，3 方 33.6% → 40.6%、4 方 29.3% → 32.7%；前一版坐 1 號對它，3 方 33.6% → 25.7%、4 方 29.3% → 17.1%。對「中」：3 方 73.1% → 77.0%、4 方 50.1% → 64.1%；對「弱」差不多（97.1% → 95.4%、82.0% → 81.7%）。全部都用它，一局中位數 134–135 秒（原本 131），98–99% 在 15 分鐘內分出勝負。兩種情況各有一個測試（`tests/match.test.ts`）。
  - 對打量不出「會不會被人騙」，所以另外寫了一個假扮真人的對手（`tools/trickster.ts`，`TRICK="6,10" npm run duel`）：打法跟「強」一樣，多一招拿只剩幾個兵的區去佯攻隔壁屯最多兵的區，把它釘住。它坐 1 號對前一版贏 35.6%／30.6%（3 方／4 方），對顧家的贏 25.6%／20.0%。但這招本身幾乎沒有用（不佯攻是 33.6%／29.3%），所以它只能當「另一種對手」，不能代表真人；真人怎麼騙，還是要靠實際玩的回報。
  - 沒留的：「來的只是一小隊、等它到時新長的兵就擋得住，就不必留守」、「來的比我少得多就迎著它打回去」（都持平，連對會佯攻的那個對手也是）、「估對方守軍時把正要進城的援軍算進去」（變差，3 方 33.0% → 30.0%、4 方 26.3% → 21.7%）。所以「有敵軍朝這裡來的區一律留守」沒有動，用幾個兵釘住一大堆兵這一招還在。
  - 參考的兩份東西：Gábor Melis 的 Planet Wars 冠軍程式檢討（<https://quotenil.com/Planet-Wars-Post-Mortem.html>）是用「已經在路上的軍隊」把每個據點的未來推一遍，算出每個據點有多少兵走了也不會丟（surplus），只准動用這些；補防送的是剛好守得住的量。上面兩件事就是這個想法的簡化版：這裡派兵是整區派光，所以「可以動用多少」變成「這一區能不能走」。它推未來時還假設對方把所有的兵都壓上來，這裡只看隔壁一步。Risk 的 Border Security Ratio（隔壁敵軍總數除以自己的兵，出自 Wolf 2005，這裡看的是 Hahn 2010 的轉述）是用來決定每回合新兵放哪裡的；這裡的兵是各區自己長的，沒有「放哪裡」這個決定，只借了「拿隔壁敵軍跟自己比」這一點。
- 起點的好壞差很多（`npm run starts`，每一方都是「強」，每個起點 150 局）：3 方時自己選臺中贏 87%、花蓮港 4%；4 方時嘉義 77%、鳳山和阿猴 1%。中部和臺南好，東部和最南邊差。對手的起點是挑離玩家最遠的區，所以常常落在東部：3 方的 3000 局裡有 1707 局有對手從臺東開局，而臺東只贏 12%。還沒處理。
- 留待之後：縱貫鐵道加速、技能點數。

## 架構上為擴充留的兩件事

1. **規則和畫面分開**。`src/sim` 是純函式的模擬，用固定節拍（每秒 10 拍）推進，只用整數與可重現的運算，不碰 DOM、不用 `Math.random`。玩家和 AI 都只送出「哪一拍、從哪到哪」的指令。
   - 因此每一局可以只存「地圖版本＋規則版本＋起始配置＋指令列表」，重播時重跑一次。
   - 之後做線上版，就是把指令改成從網路來。線上沒有暫停和 2 倍速，所以這兩個是單機模式的功能，不是核心規則。
2. **地圖是一份資料檔**（`src/maps/*.json`）。區塊形狀、據點位置、連線和地形、特色都不寫死在程式裡。之後的分區鄉鎮版只是換一份檔，`tools/build-map.mjs` 的歸併流程可以直接產生。
   - 到時要面對：358 個鄉鎮分 4–5 張圖，一張 70–90 區，手機上點不到。要在「多分幾張圖、合併小鄉鎮、加雙指縮放」之間選。

## 記錄與重播

- 存在瀏覽器（localStorage），最多 32 筆，滿了丟最舊的。可以匯出成檔案、匯入。
- 記錄帶著規則版本與地圖版本。規則或地圖改版後拿新的去播舊記錄會播不準，所以重播用的是記錄上那一版的規則和地圖（見下一節）；那一版沒留著，就標示為不能重播，不硬播。
- 重播時圖的右下角有戰報：被記錄的那位玩家攻下（紙底）或失守（墨底，附上搶走的那一方的圖記）的據點，每則留 8 秒（遊戲時間），最多同時 3 則。`Replay` 開始時本來就會把整局跑一遍，順便把每次易手記成一張表（`takes`），所以拖時間軸跳到哪裡，戰報都對得上。只有重播有；對戰中自己看得到，不多擋一塊畫面。
- 戰報也提沒換主人的大仗：你攻城沒打下來（墨底「攻某地失利」）、你守住了（紙底「守住某地」）、城外路上的遭遇（紙底「某地附近遭遇」「甲、乙間遭遇」），後面附「折 N　殲 M」（你少的兵、對方少的兵）。兩邊合計折損滿 60 才提（`BATTLE_MIN`）：兵是一個換一個，60 大約是各折 30，一個普通據點的上限是 40，等於幾乎一整城的兵拚光。拿 48 局電腦對打量過（平均一局 4 分鐘、易手的戰報 33 則）：門檻 40 平均多 10 則，太吵；60 多 6 則；80 多 4 則，但四分之一的局一則都沒有。易手的那幾場不另外提，也不附折損，本來就各有一則。
- 戰役是 `Replay` 跑整局時順便整理的（`src/sim/battles.ts`，結果在 `Replay.battles`）：只看每一拍前後 `ViewState` 的差別，把少掉的兵歸到哪一場仗，所以舊版規則的記錄也有，不用動凍結的引擎。同一方對同一區 2 秒內再打上來算同一場（幾路同時到的連成一場，隔一個派兵冷卻再來的另算）；來解圍、在城外跟攻方打起來的援軍算在那場圍城的守方；進自己的城不算折損。數字是推出來的，軍隊消失的那一拍會差一兩個兵，只拿來寫戰報。三方混戰的遭遇，「殲」是其他幾方加起來。
- 只存在那台裝置；清瀏覽器資料就沒了。

## 舊版重播

從規則 v6 起，每一版的規則引擎都留著，改了規則，之前的記錄還是能重播。v5 以前的沒有留，那些記錄只看得到結果。

- **做法是整份凍結**，不是在同一份引擎裡用版本分支。規則的改動多半是改流程（圍城、城外排隊、遭遇慢慢打），分支會全部疊在 `step()` 裡，而且每改一次都要確認沒動到所有舊版的行為。凍結的那一份不會再有人碰。
- 重播只需要規則核心：記錄裡有所有指令（含電腦的），所以不用留電腦的打法。一版是 `game.ts`、`graph.ts`、`rules.ts`、`types.ts` 四個檔，原樣複製到 `src/sim/v<N>/`，壓縮後約 6 KB（gzip 2.5 KB），重播那一版的記錄時才下載，不佔首頁。
- **畫面只認 `src/sim/engine.ts` 的 `ViewState`**，不直接認哪一版的 `GameState`。舊版引擎交出來的狀態能不能畫，編譯時就知道。之後畫面要讀新欄位：加在 `ViewState`，舊版缺的由 `v<N>/index.ts` 轉接補上，凍結的四個檔不動。畫面用到的規則數字（砲台射程、冷卻）也跟著引擎走。
- **每一版留一筆真實的記錄**當測試（`tests/fixtures/records/v<N>.json`），重播的結尾雜湊要跟記錄上的一樣。三種出錯都會在這裡失敗：規則的行為變了卻沒升版、凍結的檔案被動過、升了版卻沒凍結舊的。
- 重播畫面和記錄清單會標出「規則 v6」，因為玩法說明寫的是現行規則。

改規則的步驟：

1. `npm run freeze`：把現在這一版凍結成 `src/sim/v<N>/` 並登記到 `src/sim/engines.ts`。它讀的是 git 裡的檔案（預設 `HEAD`，也可以給 commit），所以已經動手改了也拿得到改之前的樣子。
2. 改規則，`RULES_VERSION` 加一。
3. `npm run fixture`：替新版打一局電腦對電腦的存成測試記錄。
4. `npm test`。

地圖也一樣留著。每一版是一份 JSON（約 90 KB，gzip 32 KB），放在 `src/maps/old/<地圖>.v<版本>.json`，重播那一版的記錄時才下載。改地圖的步驟：

1. `npm run freeze:map`：把現在這一版留下來並登記到 `src/maps/index.ts`（一樣讀 git 裡的檔案）。
2. 改 `tools/taiwan1901.config.mjs`，`MAP_VERSION` 加一，`npm run build:map`。新的區加在最後面。
3. 刪掉現行規則版本的測試記錄，`npm run fixture` 重打一局（它是在舊地圖上打的）；`npm test` 會檢查每一版地圖都在、舊的區編號沒變。

地圖改了、規則的程式沒改，也要當成一次改版告訴玩家，但 `RULES_VERSION` 不用動：記錄認的是「規則版本＋地圖版本」。

還沒處理的：

- 畫面大改（例如軍隊不再用「走到哪一段的第幾拍」表示）時，每個舊版都要寫轉接。這部分沒有自動測試，要開舊記錄實際看。
- 舊版只會越積越多。記錄最多 32 筆，舊的自然會被洗掉；哪天要丟掉太舊的版本，把 `OLDEST_KEPT` 往上調、刪掉資料夾和那筆測試記錄就好。

## 分享開局

想解決的是「打贏了沒辦法拿給別人看」。記錄檔要匯出再匯入，太麻煩；錄影、把整局塞進網址都太重。折衷：分享的不是那一局的過程，而是它的開局，讓別人打同一局來比。

- 一局是由「地圖、玩家起點、對手數、難度、亂數種子」決定的：對手的起點是 `pickStarts` 用玩家起點和種子算出來的，電腦的亂數也從種子來。所以網址只要帶這幾樣：`#g=<地圖版本>-<起點>-<對手數><難度 e／n／h>-<種子，36 進位>`，例如 `#g=2-13-3n-wdlgnb`。編碼和檢查在 `src/sim/opening.ts`。
- 放在 `#` 後面，不放在 `?`：純靜態網站用不到查詢字串，`#` 不會送到伺服器，GoatCounter 也不會把每個開局算成不同的頁面。
- 網址列跟著目前這一局走（`history.replaceState`，不留瀏覽記錄）：開打就換成那一局的代碼，回到自己選起點的畫面就清掉。所以對戰中重新整理，會回到同一個開局。
- 「分享開局」在暫停和結束的紙片上，重播時在畫面上方（改版前地圖的記錄沒有：現在的地圖開不出同一局）。手機交給系統的分享選單（`navigator.share`），帶一句話（結束時是「幾分幾秒拿下全島／撐了多久」）；沒有分享選單就複製網址；連剪貼簿都不能用，就把網址擺出來。成績只是那句話裡的字，不在網址裡，也沒有驗證。
- 打開帶代碼的網址：開局畫面直接把各家的起點畫出來，只有「開始」和「自己選起點」。這時點地圖不會換起點，免得想看看對手在哪裡就把開局點掉了。
- 「一樣」的範圍：起點、對手、難度、電腦用的亂數一樣。電腦是看局勢出招的，你打得不一樣，它的反應也會不一樣。
- 規則版本不放進代碼，開出來的局一律用現行規則：改了規則，舊網址還是同樣的起點，只是電腦的打法可能不同。地圖版本要對，不對的話對手的起點會算得不一樣，所以直接說這個網址開不出一樣的局，回到一般的開局畫面。看不懂的代碼當作沒有。
- 之後加別的地圖：代碼要多帶地圖的名字，沒帶的當作 `taiwan1901`。

## 使用統計

想知道的主要是三件事：大家打不打得贏（各難度的勝負比）、喜歡哪個難度和幾家對手、規則改版後還有沒有人在看舊記錄（決定舊版引擎要留多久）。

- 用 GoatCounter 的事件，一個分類組合一條 path，直接在後台看各條的次數，不用另外架東西。path 的格式列在 README。
- 勝率要自己除：`end/win/…` ÷（`end/win/…` + `end/lose/…`）。`play` 減掉三種 `end` 的總和，是開了局就關掉分頁的。
- 規則版本放在 path 裡，改版後新舊的數字自然分開，不會混在一起比。
- 分享開局記兩種次數：按了「分享開局」（`share/send`）、照帶代碼的網址開了一局（`share/play`，自己重新整理後再開也算）。開局的代碼不送出去。
- 只送分類，不送對戰內容、起家的區、打了多久。要更細的再加，加之前先想清楚要回答什麼問題。
- 腳本被擋、離線、本機開發時 `window.goatcounter` 不存在，`track.ts` 就什麼都不做。

## 介面

- 直式手機為主。整張地圖放得下，不做縮放和平移（會跟拖曳派兵搶手勢）。
- 拖曳和「點來源再點目標」兩種派兵方式都支援。
- 拖曳時在手指上方顯示目標區名、兵力對比和到達時間；一開始拖就標出到得了的區。
- 每區只顯示四樣：底色（誰的）、兵力數字、冷卻環、一個特色字。
- 不只靠顏色分辨玩家：每方的據點另有自己的形狀。
- 點一下看說明卡：區名、今天是哪裡、特色的白話解釋。
- 切到背景自動暫停。
- 畫面走古地圖風：紙色底、明體字，但數字和底色以清楚為先。
